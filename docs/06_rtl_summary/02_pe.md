# Processing Element (pe.sv)

## 模块定位
脉动阵列的最小计算单元，执行 MAC（乘累加）运算，是整个 TPU 的计算核心。每个 PE 是一个独立的流水级，数据在 PE 间脉动传播。

                  │                │

                  │         │            │

         │      [15:0]         │          │
         └──────────┬──────────┘          │
                    │                     │
         pe_switch_in ──→ [MUX]           │
                    │                     │
         ┌──────────▼──────────┐          │

         └──────────┬──────────┘          │

## 核心机制详解

### 1. 双缓冲权重寄存器（Shadow Register）
```systemverilog
// 后台加载（不影响当前计算）
if (pe_accept_w_in) begin
    weight_reg_inactive <= pe_weight_in;  // 加载新权重到后台
    pe_weight_out <= pe_weight_in;        // 同时向下传播
end

// 前台切换（同步所有 PE）
if (pe_switch_in) begin
    weight_reg_active <= weight_reg_inactive;  // 拷贝到前台
end
```

**为什么需要双缓冲？**
- Weight Stationary 架构中，权重需要**预加载**到所有 PE
- 加载期间不能影响当前层的计算
- 通过 `switch` 信号**同步切换**所有 PE 的权重（对角传播保证同步）

**时序示例（2×2 阵列加载权重）：**
```
Cycle  accept_w  PE11_inactive  PE21_inactive  switch  PE11_active  PE21_active
────────────────────────────────────────────────────────────────────────────────
  1      1         W11            -             0       (old)        (old)
  2      1         W11            W11           0       (old)        (old)
  3      0         W11            W11           1       W11          W11      ← 切换完成
  4      0         W11            W11           0       W11          W11      ← 开始计算
```

### 2. MAC 数据通路
```
组合逻辑链：
  pe_input_in ──→ fxp_mul.ina
  weight_reg_active ──→ fxp_mul.inb
  fxp_mul.out (mult_out) ──→ fxp_add.ina
  pe_psum_in ──→ fxp_add.inb
  fxp_add.out (mac_out) ──→ [寄存器] ──→ pe_psum_out

关键路径：input → mul → add → reg（约 2-3ns @ 28nm）
```

**Q8.8 定点运算细节：**
- 乘法：16bit × 16bit = 32bit 中间结果，截断回 16bit
- 加法：16bit + 16bit = 17bit 中间结果（带进位），截断回 16bit
- 溢出处理：fxp_mul/fxp_add 内部有 overflow 输出（当前未使用）

### 3. 信号传播方向与时序
```
方向规则（Weight Stationary 特性）：
  Input:  West → East  （水平流动，每拍传递一个元素）
  Weight: North → South（垂直流动，仅加载阶段，计算时固定）
  PSum:   North → South（垂直累加，每拍累加一次）
  Valid:  跟随 Input 传播
  Switch: 对角传播（PE11 → PE12/PE21 → PE22）
```

**脉动时序示例（2×2 矩阵乘法）：**
```
矩阵 A (Input) × 矩阵 W (Weight) = 矩阵 C (Output)

Cycle  PE11_input  PE11_psum  PE11_out  |  PE21_input  PE21_psum  PE21_out
──────────────────────────────────────────────────────────────────────────────
  1      A11         0         A11×W11   |    -           -          -
  2      A12         0         A12×W11   |    A11      A11×W11    A11×W11+A21×W11
  3      -           -         -         |    A12      A12×W11    (继续累加)
  4      -           -         -         |    -           -        C21 完成
```
注意：PE11 的 psum_in 始终为 0（顶部 PE），PE21 的 psum_in 来自 PE11 的 psum_out。

### 4. PE 使能机制（动态列裁剪）
```systemverilog
if (rst || !pe_enabled) begin
    // 所有输出清零
    pe_input_out <= 16'b0;
    pe_psum_out <= 16'b0;
    pe_valid_out <= 0;
    // 权重寄存器也清零（避免残留）
    weight_reg_active <= 16'b0;
    weight_reg_inactive <= 16'b0;
end
```

**应用场景：**
- 2×1 矩阵乘法：只启用第 1 列 PE，第 2 列 PE 禁用节省功耗
- systolic.sv 中通过 `pe_enabled = (1 << col_size) - 1` 控制

## 修复的 Bug（重要面试点）

### Bug 描述
```systemverilog
// 错误代码（多驱动）
always_comb begin
    weight_reg_active = weight_reg_inactive;  // 组合逻辑驱动
end

always_ff @(posedge clk) begin
    if (pe_switch_in)
        weight_reg_active <= weight_reg_inactive;  // 时序逻辑也驱动
end
```

**VCS 报错：**
```
Error: Illegal combination of drivers for net 'weight_reg_active'
```

### 修复方案
```systemverilog
// 正确代码（纯时序逻辑）
always_ff @(posedge clk or posedge rst) begin
    if (rst || !pe_enabled) begin
        weight_reg_active <= 16'b0;
    end else begin
        if (pe_switch_in) begin
            weight_reg_active <= weight_reg_inactive;
        end
        // 无 else：保持当前值（寄存器特性）
    end
end
```

**教训：**
- 一个信号只能有**一个驱动源**
- 寄存器必须用 `always_ff`，不能混用 `always_comb`
- `weight_reg_active` 需要保持值，必须是时序逻辑

## IC 设计关键知识点

### 1. 关键路径分析
```
最长路径：Input → Mul → Add → Setup
  fxp_mul: ~1.5ns (16×16 Booth 乘法器)
  fxp_add: ~0.5ns (16-bit 加法器)
  Setup:   ~0.2ns
  Total:   ~2.2ns → 最高频率约 450MHz（理论值）

实际综合后可能更慢（布线延迟、负载等），目标频率 200MHz 较为保守。
```

### 2. 面积与功耗估算
```
单个 PE 资源：
  - 寄存器：5 × 16bit = 80 FF
  - 乘法器：1 × 16bit Booth = ~500 gates
  - 加法器：1 × 16bit CLA = ~100 gates
  - 控制逻辑：~50 gates
  Total: ~650 gates/PE

2×2 阵列：4 PE × 650 = 2600 gates（不含 UB/VPU）
```

### 3. 为什么选择 Weight Stationary？
| 数据流 | 权重移动 | 输入移动 | 部分和移动 | 适用场景 |
|--------|----------|----------|------------|----------|
| Weight Stationary | 固定 | 水平 | 垂直 | 推理（W 大） |
| Output Stationary | 垂直 | 水平 | 固定 | 训练（梯度累积） |
| Row Stationary | 对角 | 对角 | 对角 | 通用（Google TPU v2/v3） |

当前项目选择 WS 因为：
- 推理场景权重矩阵远大于激活矩阵
- 权重复用率高（每个权重参与多次 MAC）
- 硬件实现简单（无需复杂路由）

### 4. 双缓冲的硬件开销
- 面积：+100%（每个 PE 多一组 16bit 寄存器）
- 功耗：+10%（inactive 寄存器仅加载时翻转）
- 性能：+∞（消除加载停顿，计算与加载完全并行）

**Trade-off 分析：**
- 小阵列（2×2）：双缓冲开销可接受
- 大阵列（64×64）：可考虑分块加载或单缓冲

## 简历话术
> 实现了 Weight Stationary PE，采用双缓冲权重寄存器实现计算与加载并行，消除权重切换停顿。使用 Q8.8 定点 MAC 运算，关键路径 2.2ns 支持 450MHz 理论频率。修复了 weight_reg_active 多驱动 Bug，严格遵循单驱动源原则，统一为纯时序逻辑设计。

## 面试高频问题
- **Q: 为什么需要双缓冲？单缓冲不行吗？**
  A: 单缓冲需要停止计算才能加载新权重，双缓冲实现计算与加载并行，吞吐率提升 100%。

- **Q: switch 信号为什么要对角传播？**
  A: 保证所有 PE 同步切换权重。如果各 PE 独立切换，会导致部分 PE 用旧权重、部分用新权重，计算结果错误。

- **Q: pe_enabled 为什么要清零权重寄存器？**
  A: 避免残留数据影响下次计算。虽然 enabled=0 时输出已清零，但寄存器残留可能导致功耗增加（翻转活动）。

- **Q: 如何优化关键路径？**
  A: 1) 使用流水线乘法器（fxp_mul_pipe）拆分为 2 级；2) 在 PE 间插入流水寄存器；3) 降低时钟频率换取面积（用 Booth-2 代替 Booth-4）。
